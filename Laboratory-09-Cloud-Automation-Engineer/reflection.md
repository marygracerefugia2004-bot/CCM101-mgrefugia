## 1. Why is automation critical when managing hundreds of cloud servers?

Automation is important because managing many servers manually takes too much time and can lead to mistakes. With automation, repeated tasks like backups can run on a schedule. It helps save time and makes server management more consistent.

## 2. What are the potential dangers of automation? What happens if a destructive typo is scheduled to run on 1,000 servers?

Automation can be dangerous when a script contains mistakes because it can repeat those mistakes quickly. If a destructive command is scheduled to run on 1,000 servers, it could delete important files or affect many systems at once. Scripts should be tested carefully, and important data should have backups.

## 3. How did writing a Bash script differ from creating a Docker Compose YAML file in Mission 6?

Writing a Bash script involved commands that run step by step to complete a task, such as creating a backup. Docker Compose YAML was different because it described how containers and services should be configured and run together. Both are useful for automation, but they have different purposes.

## 4. How has your understanding of cloud computing changed from Laboratories 1–9?

At the beginning, I understood cloud computing mainly as using online resources and services. After completing the laboratories, I learned more about infrastructure, cloud platforms, containers, storage, deployment, security, and monitoring. This activity also helped me understand how scripting and scheduled tasks can make cloud operations easier. I now see that cloud computing involves both setting up resources and maintaining them properly.
